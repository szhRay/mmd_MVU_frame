# 通用 CARD 框架

这是面向 MMD 新聊天页（chatVersion: 1）的无状态 CARD 作者工程。它保留消息读取、发送处理、主题、逐回复状态栏、舞台、流式更新和完成更新，不解析、累计、校验或保存剧情变量。

本支线是 codex/card-only；带变量系统的版本继续保留在 main。

> 导入时必须新建角色，并在创卡页确认使用“新页 / 新聊天页”。给已有角色导入无法把旧页升级为新页。

## 三步开始

### 1. 用自然语言说明需求

把角色、世界、开场白、界面和视觉感受告诉 AI。若某项尚未确定可以省略。AI 只追问会改变玩法或界面结果的问题，不要求作者说明 SDK、事件、生命周期或正则。

本支线不提供跨轮剧情状态。回复状态栏只能使用当前回复正文和消息元数据；需要变量、关系值、任务进度、物品栏或可回溯快照时，请使用 main 分支。

### 2. 按四组确认

AI 依次确认：

1. 角色设定与开场白。
2. 全局美化。
3. 功能栏、回复状态栏与可选舞台。
4. 发送、流式与完成行为。

每组先说明玩家能看到和操作什么，作者确认后才修改对应入口。

六条作者规则依次对应全局美化、发送处理、回复状态栏、舞台、流式更新和完成更新。beginning.txt 写入顶层 beginning，persona.txt 写入顶层 personality，不计入正则条数。可选的 `display-rules.json` 用于隐藏正文原始内容或简单显示替换。

使用网页 AI 时，提供 `docs/WEB_AI_AUTHORING.md`、包含作者入口的完整 JSON 和业务需求。作者在平台导入后，AI 按条目名称教作者填写内部空位；新增功能栏或显示规则时，分别提供名称、查找表达式和替换内容，由作者手动新增条目。此流程只讨论本次所需界面与行为，角色设定和开场白为可选项。

### 3. 构建与导入

~~~powershell
npm run build
~~~

默认结果：

- output/card-regex.json：创卡页导入的六键正则包。
- output/card-persona.txt：手工粘贴到角色人设。

作者明确要求本地预览时再运行：

~~~powershell
npm run preview
~~~

这会生成 output/card-preview.html。output 目录不进入 Git，发布时把构建结果作为 GitHub Release 附件。

## 固定规则

- 默认 8 条正则：2 条框架运行时、6 条作者配置，其余内容按需追加。
- 不存在插件配置或可选变量模式。
- 日常只修改 src/author。
- 功能栏按需自行增加文件、独立正则和唯一标记；默认构建器不会自动发现额外文件。
- 状态栏只保存当前回复的冻结视图；舞台仅用于覆盖消息区或整屏的大型界面。
- 正式导入始终使用 output/card-regex.json。

## 明确边界

- 只支持 MMD 新聊天页，不支持旧 MMD 或本地 SillyTavern。
- 不提供变量协议、变量注入、剧情存档、迁移或兼容层。
- 不读取或删除旧版本留下的 mvu_state。
- 不在此支线用 sdk.save 或 localStorage 重新实现剧情状态系统。
- 界面 HTML 必须遵守 docs/AUTHORING.md 的 MMD 新页容器白名单。
